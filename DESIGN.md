# Design guidelines — n1cebear's toolbox

Every UI change in this project (by a human or an agent) follows this file.

## Frontend aesthetics (source guideline)

<frontend_aesthetics>
You tend to converge toward generic, "on distribution" outputs. In frontend design, this creates what users call the "AI slop" aesthetic. Avoid this: make creative, distinctive frontends that surprise and delight. Focus on:

**Typography:** Choose fonts that are beautiful, unique, and interesting. Avoid generic fonts like Arial and Inter; opt instead for distinctive choices that elevate the frontend's aesthetics.

**Color & Theme:** Commit to a cohesive aesthetic. Use CSS variables for consistency. Dominant colors with sharp accents outperform timid, evenly-distributed palettes. Draw from IDE themes and cultural aesthetics for inspiration.

**Motion:** Use animations for effects and micro-interactions. Prioritize CSS-only solutions for HTML. Use Motion library for React when available. Focus on high-impact moments: one well-orchestrated page load with staggered reveals (animation-delay) creates more delight than scattered micro-interactions.

**Backgrounds:** Create atmosphere and depth rather than defaulting to solid colors. Layer CSS gradients, use geometric patterns, or add contextual effects that match the overall aesthetic.

Avoid generic AI-generated aesthetics:
- Overused font families (Inter, Roboto, Arial, system fonts)
- Clichéd color schemes (particularly purple gradients on white backgrounds)
- Predictable layouts and component patterns
- Cookie-cutter design that lacks context-specific character

Interpret creatively and make unexpected choices that feel genuinely designed for the context. Vary between light and dark themes, different fonts, different aesthetics. You still tend to converge on common choices (Space Grotesk, for example) across generations. Avoid this: it is critical that you think outside the box!
</frontend_aesthetics>

## How this project applies it — "Obsidian & Lapis"

The app is a villager trading hall and enchanting workshop, so the look borrows from the **enchanting table**: obsidian, lapis lazuli, emerald currency, old tomes and the floating Standard Galactic runes.

### Typography
| Role | Font | Token | Used for |
|---|---|---|---|
| Display + data | **Monocraft** (open-source, modelled on Minecraft's UI lettering; bundled in `fonts/`, SIL OFL) | `--display`, `--mono` | Page titles, brand, prices, counts, numerals |
| Body | **Bricolage Grotesque** | `--font` | All other UI text |

(The first draft used Jacquard 24 blackletter; the user rejected it.)

### Icons
Real Minecraft textures only, via `TH.icon` (js/core/icons.js), loaded at runtime from the InventivetalentDev/minecraft-assets mirror (1.21.11) and never copied into the repo. Professions use their workstation block. Enchanted things get the vanilla 1.21 item glint (`glint: true`): the real `misc/enchanted_glint_item` texture, one layer tiled at 8 icon widths, turned -10°, scrolling 27.5 s / 7.5 s per tile on x / y, added as (0.75·tex)² (vanilla's SRC_COLOR,ONE blend at Glint Strength 0.75) and masked to the sprite; its purple is the texture's own, never tinted. The Trims 3D armor uses the worn-armor variant (`misc/enchanted_glint_armor`, UV scale 0.16, same rotation, speed and blend). Avoid emoji pictographs; plain UI symbols (✓ ✕ ↻) are fine sparingly.

### Controls: "inventory slots"
Inputs, checkboxes, steppers and slider tracks are **sunken slots** (dark top-left inner edge, light bottom-right). Buttons, stepper keys and slider thumbs are **raised blocks**. The slider copies the Minecraft options-menu slider. Use the shared classes in styles.css (`.field`, `.check`, `.switch`, `.slider`, `.stepper`, `.price`, `.lvl-chips`); never ship browser-default controls.

- **Input + button rows** (e.g. Enchanting "Save item", gear rename, rename cost): one flex row, `align-items: center`, the button exactly the `.field` height (36px; the slim anvil-uses row uses 28px for both), `padding-block: 0`, `flex: none` + `white-space: nowrap` so it is sized to its label and never stretches or wraps, the input takes the rest (`flex: 1 1 0; min-width: 0`). Narrow cards may wrap the buttons under the input as a group.
- **Sunken bar, active flush** (one-of-many picker; Enchanting material bar `.ec-mats` / `.ec-mat`, `role="radio"`): ONE continuous sunken well, keys edge to edge with no gaps and no dividers, every join read from light and shadow only. Inactive keys sit on the well floor, each with its own inset (dark inner edge top-left, faint light bottom-right); together they are the well's shading (the well itself has no shadow). The chosen key rises **exactly to the surrounding surface, flush, never proud of it**: it is **see-through** (`--mk-surface: transparent`): the well itself has no fill, every *inactive* key paints the floor (`--mk-floor-bg`), so the chosen key shows the panel's real surface at that exact spot (never paint a copy of the panel gradient on the key: it restarts over the small box and reads as a separate, bigger block). No drop shadow; only a faint lit hairline on its top-left edge (Pixel: the 2px top step only), never a bright frame; it casts a neutral shadow onto the sunken key to its right (`.on + .ec-mat`); the key to its left just meets its lit edge. Only its label and icon glow in the accent (text-shadow / drop-shadow = light). Hover lifts an inactive key toward the surface (shallower inset); `:active` sinks it a hair deeper, then it becomes the flush one. No translateY press and no per-key radius (only the outer corners of the run follow the well), so these keys are NOT in the shared pressed / radius lists. Focus ring is inset (negative `outline-offset`), since the well clips. The recipe is a set of `--mk-*` tokens on the well: Classic (inventory-slot bar, crisp 1-2px edges, faint 1px top-left hairline on the chosen key), Pixel (zero-blur 2px steps), Soft (blurred insets, rule 9). **Layout** (Oct 2026): the bar fills its own "MATERIAL" box (see Layout, Enchanting item picker); keys are 56px tall (32px icon, the same size as the Armor / Tools tiles, over a 10px label, 5/2/4px padding, 2px gap, min 52px wide, equal `flex: 1 1 0`). Narrow box (< 560px: phones, the two-column squeeze): two runs of five inside the same well.

### Landing page (Overview)
`js/modules/overview.js` + `css/overview.css`: a hidden module (`hidden: true`, not a nav tab) shown when the URL has no hash and when the logo is clicked (`<a class="brand" href="#/">`). Nothing remembers the last tab: arriving fresh always lands here. One card per tool in its feature colour with a real texture on a glow pedestal, a short pitch, a live progress stat from the module's `badge(state)`, and a block-style CTA. Trims is marked "preview", Builds "soon". The grid is 4 across on wide screens, 2x2 below 1180px and one column below 700px.

### Layout
Prefer vertical **strips** (full-width rows of equal height) over uneven card grids for lists.

**Enchanting single-item layout** (Oct 2026): two columns (`.ec-layout`, grid areas `"main mode" / "main side"`). Left: the item picker as three separate segments, MATERIAL, ARMOR and TOOLS & WEAPONS (`section.panel.ec-picker`, each a size container with a top-left eyebrow heading `.ec-pick-label`, same eyebrow as PRESETS), then Enchantments. Right: the Single item / My plan switch centred on top, then the Anvil plan panel, whose first section is the Minecraft item preview under a "PREVIEW" sub-head (flat, no box of its own). All picker icons are 32px (integer 2x of the 16px textures), tiles one uniform height. Column counts keep rows full: Tools & weapons (16 items) 8 per row = two rows on desktop, 4 per row when its box is < 560px; Armor (6) one row of 6, 3 + 3 below that. **Equal column ends**: both columns stretch to the row; the sidebar is sticky, capped at the viewport and scrolls; the Anvil plan panel fills it (name field + Add to plan / Done rest at its bottom, `margin-top: auto`), so it reaches the viewport bottom while scrolling and ends exactly with the left column at the end; if the plan is taller, the Enchantments panel grows to match. Below 980px one column: switch, left boxes, plan. The plan view (`.ec-pv`) puts the same switch on top of its right column (centred above the empty-plan card). The PRESETS row has no description line (it changed per preset and made the layout jump); each preset's reason lives in its button tooltip.

**Label-left rows** (grouped button rows inside one panel; the Enchantments panel's PRESETS): each row is `[label | buttons]` (`.ec-rowbox > .ec-row > .ec-row-label + buttons`). All labels use one eyebrow style (Monocraft 12px, uppercase, 1px tracking, muted; never a card `h3` size) in one fixed-width column (`--ec-lbl-w`, 84px) so every row's buttons start on the same line; the label is centred on the **first line** of its buttons (`--ec-row-h`), the buttons fill the rest and may wrap. The panel is a size container: below ~600px of panel width (phones, the two-column squeeze) the label goes back above its row. No dividers or boxes between rows; spacing only.

**Page head** (`div.page-head`, shared CSS in styles.css): every tool tab opens with its title **centred** and **no subtext** paragraph (help belongs in the UI itself, as a short hint where it is needed). Layout is a 3-column grid `1fr | title | 1fr`: the first child (the `h2`, or a wrapper holding it) sits in the centre column, any further child (the hall wizard's "Back to hall"; Enchanting's Single item / My plan switch moved to the top of its right column) sits right-aligned in the right column; at <= 720px everything stacks, centred, controls under the title.

### Language
Game terms (enchantments, items, villagers, trims) use Mojang's official translations through `TH.i18n`. The tool's own UI text stays English.

### Colour
- **Dark (default), "Obsidian":** near-black violet-obsidian base. **Lapis** is for links; **gold** is for prices and treasure (never themed); `--enchant` is the UI colour for enchanted / perfect states (the icon glint itself is the real glint texture, see Icons). Everything else that is "active" follows the **per-feature accent** below.
- **Light, "Parchment":** warm paper and sepia ink, using the same hues in deeper shades. It reads like a written ledger, not a white SaaS page.
- **Per-feature accent.** Every tool owns one colour and it drives *all* highlights inside it: primary buttons, checkboxes and check marks, switches, slider thumbs, selected / active states, focus rings, progress bars and rings, the active nav marker and badges, text selection. `app.js` sets `<html data-tool="hall|enchanting|trims|builds|portal|overview">` on every route; `styles.css` derives the whole family (`--accent`, `--accent-2`, `--accent-deep`, `--accent-ink`, `--accent-soft`, `--select`, `--select-soft`, `--glow-b`) from one value, `--tc`, under `:root[data-tool]`. Only the four palette tokens `--c-hall/--c-ench/--c-trim/--c-build/--c-home` (plus `--on-accent`, `--mix-hi`) differ per theme.

- **Module CSS uses only the tokens** (`var(--accent)`, `var(--select)`, ...) for primary, selected, checked and focus states, so it recolours itself. Do not hard-code greens or violets, and do not use `--lapis` for focus. Gold stays for prices; `--tier-*` and profession / trim colours are data colours and are not themed.
- Each nav tab shows its own feature colour (underline, icon glow, badge) via `.nav-item[data-tool]` so the system reads clearly even when another tool is active.
- Never use purple gradients as decoration; purple appears only as Enchanting's accent and the enchant glint.
- Always use tokens (`var(--...)`); never hard-code a colour in module CSS except for data colours like profession or trim colours.

### Shape and surface
- Small radii (`--radius: 6px`) for a blocky feel. Panels have a 1px top highlight and a darker bottom edge, like an inventory slot.
- Primary buttons have a 3px "block" under-shadow that compresses on `:active`.

### Surface tiers (neumorphic styles: Pixel + Soft; `css/style-neu.css`)
Every surface in the two neumorphic styles (Pixel and Soft, see "Style toggle") belongs to exactly one tier; the tiers, hooks and lighting are shared (`:root[data-neu]`), only the recipes differ (see "Pixel vs Soft" below). Light always falls from the top-left (light shadow top-left, dark shadow bottom-right; inset reverses it). **Accent lives only in light, never in shadow:** every shadow is neutral (`--neu-lo`); the feature colour only appears on the side that catches the light (inset/selected: bottom-right inner rim, glow from the lower-right, lit bevel steps; raised accent surfaces: the top-left highlight). **The accent light of a selected control is drawn in the background, never as an inset box-shadow:** an inset shadow cannot fade along its edge, so the old `inset -3px -3px` accent rim ran the full height of the right edge / full width of the bottom and, with the radius and blur, tinted the top and left edges (bug fixed Oct 2026). `--neu-sel-inset*` are neutral only; `--neu-sel-bg` carries a 1px lit rim in the transparent 1px border (`linear-gradient(to bottom right, transparent 50%, rim 92%) border-box` under an opaque `padding-box` face: the 50% line runs exactly through the top-right and bottom-left corners, so nothing lights the top-left half) plus a lower-right glow clamped below mid-height; the Pixel bevel's lit accent steps (2px thick, crisp) fade out along their length toward those corners in one continuous ramp (`--neu-px-acc-h/-v`: transparent 16% → `--neu-px-acc-mid` 52% → full 86%; the old hard 0/34/62% stops showed as three blocks on wide strips). Soft has no ring at all (see "Pixel vs Soft"). Every selected control therefore needs a 1px transparent border (the nav tabs and the switch track have one). **Classic** follows the same rule as a pressed-in inventory slot: `border-color: var(--sel-edge)` (neutral dark `--sel-sh` top + left, neutral `--line-2` bottom + right) and `box-shadow: var(--sel-slot)` (2px dark inset top-left listed first, so it covers the corners, then a 2px accent inset bottom-right) plus accent text / accent-soft fill (styles.css). No full accent outline, ring or all-round accent glow on a selected state; those read as focus, which keeps its own outline. Module CSS never draws its own container surface: use the hooks below and the tokens decide.

Rules:
1. **Never nest a segment in a segment.** A container inside a `.panel` is flat (faint `--neu-flat` tint, no shadow); `.panel .panel` does this automatically.
2. **Segments carry no stepped bevel**; only T2 controls do. A segment gets only its crisp stepped shadow and the 1px rim, so it reads as the same blocky family but stays visibly calmer than its controls (T1 < T2). Selected T2 flips the bevel.
3. **Two kinds of grouped keys.** (a) **Joined groups** for independent or many-of-many keys (the top-right toolbar, the top nav strip, canvas `.hc-grp`): one sunken strip, keys 2px apart (the well is the divider), square inner joins; only the first key's left corners and the last key's right corners are rounded (`--neu-r-ctl`), the strip has 12px. Buttons joined in a group use `--neu-ctl-sq` / `--neu-t2-grp` (straight bevel, small **dark-only** shadow, so the 2px gap is never lit). (b) **Exclusive toggles** (`.seg`, one-of-N: Enchanting "Single item / My plan" `.ec-mode` and "I want / Already on it" `.ec-ownseg`, the ⋯ menu style switcher, Trims skin / arm pickers, hall sort, builds filter): one sunken well with ONE knob. Inactive keys lie flat on the well floor (no surface, bevel or shadow); the active key is a raised T2 key with all four corners rounded (`--neu-r-ctl`, `--neu-ctl` + `--neu-knob`: neutral dark shadow bottom-right, 1px light top-left), accent only in its label. Never a square edge between the two sides. Classic: same knob (rounded keys, the raised `--shadow` key with a 2px accent line on its lit TOP edge). **The knob slides** when the selection changes, with the `.switch` knob's motion (Classic `.18s cubic-bezier(.3, 1.4, .5, 1)`, Pixel `.16s steps(5, end)`, Soft `.3s var(--neu-ease)`; `prefers-reduced-motion` jumps). Mechanism: the knob is the seg's `::before` (styles.css "SLIDING KNOB", look per style in style-neu.css), sized and placed by `--seg-x/-y/-w/-h` = the active key's box; the keys sit above it and the active key draws no surface of its own, only its accent label. `TH.util.segKnob` (util.js) sets those vars plus `data-knob` (`on` = sliding, `still` = placed without motion, `none` = nothing selected) for every `.seg` automatically: a MutationObserver on `<body>` sees `.on` / `aria-checked` / `aria-pressed` changes and newly rendered segs, a ResizeObserver and style/font changes re-place without motion. First paint never slides; when a module re-renders the whole seg, the new element slides from the last position remembered under its `aria-label` / `aria-labelledby` / `id` only if the selection changed (so give every `.seg` a stable `aria-label`). No module JS is needed; without the helper the `.on` key draws the knob itself.
4. **Top bar:** nav strip and toolbar strip are both 48px tall, in their own layout box (no negative margins, nothing overflows), tabs 40px centred (4px well around them); the toolbar keys are 40px too (3px padding + 1px border), so tabs and keys share one top and bottom line (phones keep the compact 44px toolbar strip with 36px keys); the toolbar sits on the right content edge (`.topbar-actions { margin-left: auto }`).
5. Exceptions are documented in the CSS: saved-gear cards (`.ec-gear-card`) are compact T2 cards; `.ec-preview` (inside the Anvil plan panel) is an object floating on the panel, no well; `.ec-pi.done` is a compact one-line segment; dialogs/menus/tooltips are overlays with a bigger shadow.
6. New feature checklist: container = `.panel`; clickable things = existing control classes (or add the class to the T2 list in `style-neu.css`); inputs = `.field`; grouped controls = a wrapper listed in the segmented-group rule. Do not set `background`, `box-shadow` or `border-radius` on containers/controls in module CSS for the neumorphic styles (Pixel, Soft). Classic is untouched.
7. **Switch** (`.switch`): T-1 well track (`--neu-r-ctl`, 44x24) with a T2 knob (`--neu-ctl` + `--neu-raised-xs`, `--neu-r-xs`) carrying a 4px "lamp" pixel. Checked: track keeps its neutral inset, accent glow from the lower-right + accent bottom-right rim; the knob's lit top-left bevel steps and highlight take the accent and the lamp lights up. Travel is stepped (`steps(5)`). (Pixel. Soft: rounded-rect track and knob, no lamp, the checked knob takes an accent-tinted face + top-left accent highlight, eased travel.) The label next to it (e.g. `.tr-sync`) never sinks; pressing presses the knob.
8. **Accent only in light**: never mix the accent into a `--neu-lo` shadow or into a positive-offset (bottom-right) drop shadow; accent glows on raised things sit top-left (negative offset).
9. **Each side gets only its own light (no halos).** Raised: light ONLY top-left, dark ONLY bottom-right. Inset/wells: inner shadow top-left, inner light bottom-right, no bright halo around a well. A blurred shadow must not wrap past its own side: for offset `o` (both axes), blur `B` and spread `s` the spill onto the opposite edge is `s + B - o`, keep it `<= 0` (write it as `o = reach / 2`, `s = o - B`). This holds for outer and inset shadows, light and dark. No 1px light borders on the shadow side: overlay borders are `var(--neu-edge) transparent transparent var(--neu-edge)`, the top bar band has no light line under it. (Bug fixed Oct 2026: the old `-2px -2px 6px hi` style halos spilled 1-16px past the bottom/right edges and showed through the semi-transparent dark steps as a bright outline; the transparent 1px borders also left a strip of the lighter gradient outside the bevel / inset rim.)
10. **Sunken bar, active flush** (material bar, see Controls): an exception to "selected = inset with accent rim". The bar is a T-1 well, its keys live on the well floor, and the selected key rises to the T1 surface level (flush, no outer shadow, no accent in any shadow); its label glows instead.
11. **Sticky action rows** are ONE shared pattern, `.th-act-row` (styles.css): standalone buttons in equal columns, no strip behind them, the LAST row inside a padded panel; `position: sticky; bottom: calc(var(--bottom-bar, 0px) + var(--act-pp))` where `--act-pp` = the panel's padding (the panel sets it; Pixel/Soft use `--neu-pad` via style-neu.css), so while the content scrolls the row floats with a neutral `drop-shadow` lift and at the end it rests exactly in place, flush with the panel's inner edge. In a sticky scrolling sidebar it floats at the bottom of the sidebar's scroll area; when the sidebar stacks it floats over the viewport above the phone tab bar (`--bottom-bar` is 0 above 640px, so no breakpoint is needed). Users: the planner wizard (Back / Next `.hl-wiz-nav`, last row of the "Total so far" panel; the old full-width `.hl-wiz-foot` bar is gone) and Enchanting ("Add to plan" / "Done" in the Anvil plan, `.ec-plan { --act-pp: 16px }`, stacked at <=640px); both size their sticky sidebar with a small fitSide() so the row is on screen without scrolling.

#### Pixel vs Soft
Both use every tier, hook and token above. **Pixel** (`data-style="pixel"`, "Minecraft neumorphism") draws the chrome in game pixels: 2px stepped bevels on T2 controls and nav tabs, crisp zero-blur stepped T1 shadows, a dotted 2x2 nav mark, the switch lamp pixel and `steps()` motion. **Soft** (`data-style="soft"`, smooth neumorphism; the last section of `style-neu.css`) sets every bevel token to `none` (so `--neu-ctl` is the plain gradient), uses blurred shadow pairs, **soft edges** (the shape boundary is drawn only by blurred light and shadow, never by a line: every raised recipe = outer pair + a fainter inner pair on the same sides, `--neu-lo-in` / `--neu-hi-in`, so the face shades into its own shadow; bigger blur with spread = offset - blur, so rule 9 spill is 0 and the shadow box ends at or inside the edge; `--neu-rim-hi/-lo` and `--neu-edge` transparent; gentler `--neu-grad` painted `border-box` so no 1px sliver repeats into the transparent border; wells (`--neu-well`) closer to the face; slightly lower contrast `--neu-lo/-hi`; selected = no 1px ring (`--neu-sel-ring` empty), `--neu-sel-bg` is a diagonal `--neu-sel-wash` + a lower-right glow peaking just inside the edge; the seg knob, switch knob and accent faces lose their 1px hairlines), slightly larger radii (segments 22px, controls 10px, tiles 16px, groups 14px, small keys 8px, boxes/knobs 6px) and eased motion (`--neu-ease`, ~.2-.3s). Soft keeps the blocky identity in shape: **rounded rectangles only, no circles and no full pills** (switch knob, slider thumb, nav mark, chips, bars, eyebrow, scrollbar). Content stays Minecraft in both: Monocraft numerals, pixel textures and glyphs.

### Background
A layered, fixed atmosphere (`#atmosphere` in index.html, mobs built by `initAtmosphere()` in app.js):
- a faint pixel grid,
- a lapis glow at the top-left and an emerald glow at the bottom-right,
- minimal **mob faces** (blaze, creeper, zombie, skeleton, enderman, villager, ghast, spider, wolf, ...) rising slowly: small, low opacity (`--mob-op`), `image-rendering: pixelated`. Each is the 8x8 (or 8x10) front-of-head region cropped from the real entity skin with `background-size/position`; the table is `TH.icon.mobFaces` and the texture source is the same CDN mirror as `TH.icon` (`entity/...`), cached by sw.js and warmed with the icons. Local `file://` mode still uses the CDN for these.

Faces stop under `prefers-reduced-motion` (not even created).

### Chrome
- **Scrollbar:** themed (sunken track, raised block thumb; `::-webkit-scrollbar`, with `scrollbar-width: thin` + `scrollbar-color` only inside `@supports not selector(::-webkit-scrollbar)` for Firefox), `scrollbar-gutter: stable` on `html` so layout never shifts. **One global rule for the page and every inner scroll container** (styles.css; Pixel/Soft re-shape it once in style-neu.css). - **Scroll edge shadows:** every scroll container shows a neutral shade at an edge only while more content lies beyond it, as if the surface were cut there (styles.css "scroll edge shadows", style-neu.css section of the same name). Two sticky pseudo-elements per container (`::before` = start edge, `::after` = end edge) overlay the content and take no room. **Opt in** with `.th-scroll` (vertical) / `.th-scroll-x` (horizontal), or add the class to both selector lists in styles.css and to `SCROLL_Y` / `SCROLL_X` in util.js. ### Tooltips (app tooltip vs. Minecraft-style preview)
- **App tooltip** (`TH.util.tooltip(target, content, opts)` -> dispose fn; CSS in `styles.css`): the one tooltip for the whole toolbox for icon buttons, chips, tiles, badges and any hover hint. Rich content uses `.th-tooltip-title` (text colour, 600), `.th-tooltip-sub` (muted 11.5px, may repeat) and `.th-tooltip-tag` (tiny accent pill for rarity/state).
